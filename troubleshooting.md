# Troubleshooting

Symptom, cause, and fix, assembled from the failure modes actually hit while producing the book's results (Appendix A's table, extended with the gotchas recorded in the `experiments/` ledgers). If a symptom isn't here, check the chapter's ledger: every known caveat is written down there.

| Symptom | Cause | Fix |
|---|---|---|
| Attention analysis fails, or `output_attentions` returns nothing useful | Default SDPA attention kernels do not return per-head weights | Load the model with `attn_implementation="eager"` (Chapters 3 and 5 do this explicitly) |
| First run of a notebook takes many minutes, later runs are fast | First run downloads model weights and datasets (GPT-2 ~550 MB, Qwen-0.5B ~950 MB fp32, ch10 SAE ~330 MB, Gemma-2-2B ~5 GB if enabled) | Expected; everything caches under `~/.cache/huggingface/`. On Colab, the pinned `%pip` cell adds 2–5 min for heavy stacks |
| Colab prompts "Restart runtime" after the install cell | The pinned `numpy==1.26.4` is older than Colab's preinstalled NumPy 2.x; pip downgrades it | Expected: restart when asked, re-run from the top. The pin exists so your numbers match the book's |
| `run_notebooks.py` reports `SKIP … missing dependency group(s)` | Notebook declares `llm` or `mechinterp` in its metadata and the marker module (`torch` / `transformer_lens`) isn't installed | `make setup-ml` (Chapters 2–9, 11–13) or `make setup-mechinterp` (Chapter 10) |
| Installing `mechinterp` group removed my PyTorch/Transformers stack | `uv sync` is exact: syncing only the `mechinterp` group uninstalls everything not named | Always use `make setup-mechinterp` (installs `llm` + `mechinterp` together, on purpose) |
| Version conflicts around `transformers` when adding transformer-lens/sae-lens to your own env | `transformer-lens` and `sae-lens` pin their own `transformers` version ranges | Keep them in the separate `mechinterp` dependency group as the repo does; let the resolver pick versions (ledger-tested: transformer-lens 2.9.0, sae-lens 6.5.3, transformers 4.57.6) |
| Notebook killed / machine swaps hard on a 0.5B-model chapter (out of memory) | fp32 0.5B weights ≈ 1 GB plus activations and batch generation on a small-RAM machine, or other apps competing for memory | Run in smoke mode (`BOOK_SMOKE=1`), reduce batch size, or move to Colab, where a free T4 (16 GB) fits every lab by design |
| Gemma Scope cell fails with HTTP 401/403 | `google/gemma-2-2b` is gated on the Hugging Face Hub | Accept the license on the model page, authenticate (`huggingface-cli login` or `HF_TOKEN`), set `RUN_GEMMA = True`, budget ~5 GB download (bf16 fits a T4) |
| Chapter 10's SAE sections just print skip notes | You are in smoke mode; `BOOK_SMOKE=1` skips the SAE download, feature dashboard, and steering demo | Re-run in full mode (unset `BOOK_SMOKE`) |
| Chapters 5/6/8 warn `models/ch04-specimen` is missing and quick-train a fallback | The 268 MB fine-tuned specimen is not in the GitHub repo | Run the Chapter 4 notebook in full mode first to build it; otherwise accept the `bert-mini` fallback (4 layers × 4 heads; plots and numbers will differ from the book's) |
| Chapter 12's adapter cell prints instructions and skips | It needs `BOOK_CH12_ADAPTER` pointing at the downloaded LoRA checkpoint, plus GPU/MPS (it skips on CPU by design, since a 1.5B greedy pass on plain CPU is too slow) | Set the env var to the checkpoint dir and run on MPS/CUDA; the notebook still passes without it |
| Your trained-model metrics differ from the ledger despite the same seed | MPS/GPU training is not bit-reproducible; the ch12 ledger recorded 0/20 vs 5/20 acknowledged flips for MPS-fp16 vs CPU-fp32 with identical code and seed | Set `BOOK_DEVICE=cpu` and compare against the device/dtype noted in the chapter's ledger before suspecting a bug |
| Borderline generation results shift by one item on different hardware | Float kernels differ across CPUs/GPUs; greedy decoding flips on near-ties (ch13 ledger expects ±1 question) | Normal: compare qualitative findings; exact digits are only guaranteed on the ledger's recorded setup |
| `faiss` import or install fails (Chapter 13) | Wrong package name or platform wheel; the project uses CPU FAISS | Install `faiss-cpu` (repo pins `faiss-cpu>=1.8`; ledger ran 1.14.3; Colab cell pins `faiss-cpu==1.14.*`). Don't build FAISS from source and don't install `faiss-gpu` for this lab |
| A notebook dies after exactly 20 minutes under `run_notebooks.py` | Per-notebook timeout, default 1200 s (`BOOK_NB_TIMEOUT`) | Raise it, e.g. `BOOK_NB_TIMEOUT=3600 make nb-run`, or run smoke mode first to confirm correctness cheaply |
| Endless tokenizer parallelism warnings in logs | Hugging Face tokenizers warn when notebooks fork worker processes | Cosmetic; set `TOKENIZERS_PARALLELISM=false` in your shell profile |
| Progress-bar widget junk saved inside `.ipynb` outputs (Chapter 10 patching) | `tqdm.auto` inside Jupyter ignores `TQDM_DISABLE` | The notebook already monkeypatches `patching.tqdm`; if you write your own patching loops, do the same before a `BOOK_NB_SAVE=1` run |
| sae-lens prints a `model_from_pretrained_kwargs` UserWarning (Chapter 10) | False alarm in the sae-lens 6.5.3 release for this SAE (`center_writing_weights=True` is transformer-lens's default anyway) | Ignore it; the notebook suppresses it with a targeted filter and an explanatory comment |
| Rendered book is missing formats you built earlier | Each per-format Quarto target wipes and rebuilds `_book/` | Use `make all` to produce every format in one render |
| SHAP/Captum steps unexpectedly slow on Apple Silicon | Some SHAP and Captum ops silently fall back from MPS to CPU | Known and harmless; the ledgers' wall-clock times already include these fallbacks; force `BOOK_DEVICE=cpu` if you want honest apples-to-apples timing |
| Chapter 1 exercise gives numerically identical results after changing the cue words | Only the cue *strings* change, not the RNG stream, so iid 0.950 / shifted 0.515 reproduce exactly | Not a bug; vary `MY_CUE_CORR` (or the seed) to see the numbers move |
