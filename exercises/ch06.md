## Exercise 6.1: A random-direction control for CAV-lite *(warm-up)*

**Goal.** The mean-difference concept vector scores held-out AUC 0.773 with zero gradient steps. Before being impressed, add the control the chapter implies but does not run: what AUC does a *random* 768-d direction get at the same layer?

**Steps.**
1. In the concept-direction cell (layer 3), keep the projection-and-AUC code.
2. Replace the mean-difference vector with `rng.standard_normal(768)`, unit-normalized, for 20 seeded draws.
3. Report the distribution of random-direction AUCs (fold each AUC as `max(auc, 1-auc)`, since a random direction's sign is arbitrary) next to the real 0.773.

**Hint.** Everything after the vector definition is reusable; the loop is ~5 lines.

**Solution sketch.** You should see roughly chance-level AUCs (centered near 0.5 after sign-folding, with spread from the 150-item test set) against the committed 0.773. The gap is the evidence that one labeled mean-difference actually finds structure. Keep the folded-random spread as your noise band whenever you interpret concept-direction AUCs on your own data.

## Exercise 6.2: Raise the budget on the honest failure *(core)*

**Goal.** The ledger keeps one counterfactual failure: a slur-dense tweet where 5 greedy edits only moved p(hate) from 0.893 to 0.797 (signal spread across many slurs). Test the chapter's diagnosis: is this a budget problem or a distributed-signal problem?

**Steps.**
1. In the counterfactual cell, raise the edit budget from 5 to 12 for the failing tweet only.
2. Also widen the substitution pool (the default is a 10-word neutral pool) to ~25 neutral words.
3. Track the full p(hate) trajectory per edit; note whether it crosses 0.5 and how many *distinct* slur tokens the greedy search had to touch.
4. Compare the edit count against the flipping tweets' mean of 3.0 edits.

**Hint.** If p decays roughly linearly per edit (each edit removing one of many similar contributors), that supports "distributed signal"; if it plateaus, the model may be reading something greedy word-level edits cannot reach.

**Solution sketch.** Change two constants, filter the loop to the failing example, plot the trajectory. Not in the ledger beyond the 5-edit point (0.797); record what you find and compare against the chapter's number. Either outcome sharpens the chapter's claim that "search failure describes the model too": a late flip quantifies how much more redundant the evidence was; no flip at 12 edits is a stronger statement than the ledger's.

## Exercise 6.3: How little data does the probe need to beat the model? *(stretch)*

**Goal.** The chapter's central caution, measured: a linear probe trained on 450 tweets hits 0.720 at layer 3, above the specimen's own 0.676 validation accuracy. Find the smallest training set for which the probe still wins.

**Steps.**
1. In the probing cell, wrap the layer-3 probe in a loop over train sizes `[25, 50, 100, 200, 300, 450]` (keep the same 150-tweet held-out set fixed).
2. At each size, also train the shuffled-label control probe and report selectivity (task − control); the full-size ledger value is 0.193.
3. Plot probe accuracy vs train size with a horizontal line at 0.676 (the model head) and at 0.593 (layer-0 majority baseline).

**Hint.** Resample the training subset with a fixed seed per size, or better, average over 5 seeded subsamples per size; 25-tweet probes are noisy.

**Solution sketch.** One nested loop, ~10 lines. Anchors from the ledger: 450 gives 0.720, majority 0.593, control 0.507–0.607. The intermediate curve is unledgered. Record where it crosses 0.676 and compare against the chapter's endpoint. Watch selectivity at tiny sizes: if control accuracy rises as task accuracy falls, small-sample probes are memorizing, and "the representation contains X" claims need the selectivity discount most exactly when data is scarce.
