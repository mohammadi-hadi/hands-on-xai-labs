## Exercise 13.1: Move the format example, move the bug *(warm-up)*

**Goal.** The lab's accidental headline: 2 of 3 emitted citations point at `doc-6` (the document used as the *format example in the system prompt*, never retrieved). Earlier, a no-example prompt degenerated to bare citation markers (accuracy 0.12). Test whether the example-leak follows the example.

**Steps.**
1. In the prompt-construction cell, swap the format example to cite a different doc id (e.g. `[doc-12]`), rerun the 8-question citation lab, and count citations of the new example id.
2. Then try an example with a *fictional* id (`[doc-99]`) that exists in no corpus.
3. Recompute answer accuracy, citations emitted, and citation precision for each variant (anchors: 0.88 accuracy, 3 citations, precision 0.33).

**Hint.** The support checker already classifies citations to non-retrieved docs as unsupported ("hallucinated pointer"); a `[doc-99]` citation is the smoking gun that the model copies the example rather than grounding.

**Solution sketch.** One string edit per variant, rerun two cells. Unledgered beyond the `doc-6` run. Record what you find and compare against the chapter's numbers. If the leak follows the example id, you have reproduced "prompt scaffolding moves failures around, it doesn't remove them" as a controlled experiment, and you get a concrete review-checklist item for any few-shot RAG prompt: never use a real corpus id in the example.

## Exercise 13.2: Upgrade the support heuristic to NLI *(core)*

**Goal.** Support is currently content-word overlap >= 0.5, a screening test the ledger admits can be fooled by paraphrase (false unsupported) and keyword stuffing (false supported). Replace it with an entailment check and measure how the audit verdicts change.

**Steps.**
1. Load `roberta-large-mnli` (the ledger names it as the intended stretch upgrade; ~1.4 GB download).
2. Write `nli_supported(answer_sentence, doc_text)`: premise = doc excerpt, hypothesis = answer sentence; supported iff entailment is the argmax label.
3. Rerun the 8-question audit scoring citations and uncited-but-used docs with both heuristics; build a 2×2 table (overlap says supported / NLI says supported).
4. Read the disagreement cells. Which heuristic is right, by your own judgment?

**Hint.** Chunk long docs into sentences and take max entailment over chunks. MNLI models were trained on sentence pairs, not 1,000-character premises. Keep the overlap score in the log; the point is the *delta*, not replacing one opaque verdict with another.

**Solution sketch.** ~20 lines: one pipeline call, a chunking loop, two audit passes. Anchors: overlap-based precision 0.33, 8 uncited-but-used at overlap 0.70–1.00. NLI verdicts are unledgered. Record what you find and compare. Deliverable: one sentence on cost (NLI calls per request vs the overlap check) because Chapter 13's whole frame is that audit quality is bought in model calls (compare the SHAP budget curve from Chapter 4).

## Exercise 13.3: Stress-test the drift monitor's detection threshold *(stretch)*

**Goal.** The monitor's noise floor is 0.0004 bits (weeks 2–3); the week-4 rename (50% of product queries) lands at 10x floor and weeks 5–6 at ~42–47x, while `gold_in_top3` stayed 1.000 throughout. Find the smallest drift the monitor can see, and check the temperature knob that sets its sensitivity.

**Steps.**
1. In the drift-simulation cell, parameterize the week-4 rename fraction: rerun the 6-week simulation with 10%, 25%, 50% of product queries saying "Kestrel".
2. For each fraction, record the week-4 JS divergence in units of the noise floor; find where the signal drops below ~3x floor (your practical detection limit).
3. Separately, vary the attribution softmax temperature (default 0.1) to 0.05 and 0.5 at the 50% rename level, and watch both the noise floor and the drift signal move.

**Hint.** Temperature controls how peaked the attribution distribution is: colder = spikier = bigger JS jumps but also a noisier floor. The right metric is signal-to-floor *ratio*, not raw bits.

**Solution sketch.** Two loops around the existing weekly simulation (each full run is ~25 s CPU). Anchors: 50% gives 0.0040 bits (10x floor), 100% gives 0.0167–0.0187 (~42–47x). The 10%/25% points and the temperature sensitivity are unledgered. Record what you find and compare against the chapter's numbers. Deliverable: an alerting rule you could ship ("alert when weekly JS > Nx trailing 3-week floor"), which is the chapter's monitoring loop made operational.
